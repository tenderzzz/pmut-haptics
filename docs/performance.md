# 性能分析

2026-10-14 对最终分块实现测量。原始重复样本、环境与误差保存于 [benchmark.json](results/benchmark.json)。

## 公平比较的范围

比较同一个障板圆活塞快速核：
- 参考实现：Python 逐场点调用，每个场点内仍使用 NumPy 对阵元求和。
- 分块实现：一批场点形成 M_block×N 传递矩阵，批量求和。
- 二者均使用 float64 坐标、complex128 声压、相同阵列、焦距与采样点。

每个实现/规模独立启动进程，预热 1 次、测量 5 次，报告中位数和范围。工作进程将 OMP、OpenBLAS、MKL、Accelerate 等线程环境变量设为 1；未做 CPU 核心绑定，也未保证操作系统没有其他负载。当前 macOS 库未被 threadpoolctl 识别，线程数是环境设置，不能将其描述为经过运行时计数核实的单核基准。

不计入导入、阵列准备、绘图、文件保存和浏览器渲染。验证阶段在稀疏场点对照参考实现；独立测试还有随机点一致性检查。没有把“完整表面积分改为近似模型”计入加速。

## 本机结果

环境：macOS 26.6.2 arm64，10 个逻辑 CPU；Python 3.12.14、NumPy 2.5.4、SciPy 1.18.1。

| 阵列 | 目标网格 | 参考中位 ms | 分块中位 ms | 加速比 | 分块峰值 RSS MiB |
| --- | --- | ---: | ---: | ---: | ---: |
| 8×8 | 32×32 | 11.476 | 1.232 | 9.32× | 102.3 |
| 12×12 | 64×64 | 52.023 | 10.892 | 4.78× | 129.0 |
| 16×16 | 96×96 | 136.268 | 43.653 | 3.12× | 170.0 |

三档分块重复耗时范围依次为 1.227–1.268 ms、10.797–10.973 ms、43.322–43.872 ms；稀疏核对的最大相对 L2 误差约 3.03×10⁻¹⁶。这里的加速比只代表本机和本组输入，不能写成所有仿真普遍快 9 倍。

峰值 RSS 由每个新工作进程的 resource 记录，包含解释器、导入库和临时数组，不等于纯算法工作区。参考版峰值约 97 MiB，向量化用更多临时内存换取批量计算效率。主场景 metrics 中的 simulation_seconds 是整次计算的一次观测，与此受控内核基准的口径不同。

## 时间与空间复杂度

设场点数 M、阵元数 N、轨迹帧数 T、块大小 B：

| 操作 | 时间量级 | 主要空间 |
| --- | --- | --- |
| 单帧参考/分块声场 | O(MN) | 参考 O(N+M)，分块 O(BN+M) |
| 轨迹声场 | 几何核 O(MN)，相位叠加 O(MNT) | O(BN+MT) |
| 有限平面积分 | O(M)，逐轨迹为 O(MT) | 在已有输出上积分 |
| 原始全矩阵方式 | 同样 O(MN) | 若不分块，将需要 O(MN) 临时空间 |

加速来自减少 Python 调用和复用向量化运算，没有改变单帧渐近复杂度。轨迹把同一目标平面的距离、指向性和传播核复用于全部焦点，从而避免重复计算昂贵的几何核；但矩阵乘法与输出仍随 T 增加。

B 同时受 chunk_points 与 max_transfer_mb 的约束，暂按每个场点/阵元约 80 字节估算几何及复数临时数组。这个估算不是整个进程的硬内存限制。轨迹输出另外限制到 1000 万个平面采样值，防止保存全部帧造成过大分配。

## 可以继续验证的优化

如后续需要更大的阵列或实时驱动，应先确定吞吐、延迟、内存和数值误差目标，再评估只计算必要 ROI、跨实验复用几何、FFT/角谱方法或 GPU。不同算法可能改变边界假设或近似误差，应重新建立参考验证。当前项目没有声称 GPU、实时硬件闭环或端到端实时触觉能力。
